# Änderungen – 05.11.2026

## 1. Least-Privilege Permission System

### ContextBuilder: defaultPermissions
- **Datei:** `engine/src/main/java/de/augmentia/oc/engine/runtime/context/ContextBuilder.java`
- Neues Feld `defaultPermissions` (List<Rule>)
- Neuer Konstruktor mit `List<Rule> defaultPermissions` Parameter
- Bestehende Konstruktoren delegieren mit `List.of()` (keine Änderung für bestehende Aufrufer)
- `prepare()` prepended `defaultPermissions` vor Agent- und Session-Regeln

### Static Factory: leastPrivilegeDefaults()
Statische Methode in `ContextBuilder` liefert ein vorkonfiguriertes Regel-Set
(**echtes Least Privilege** – deny all, alles fragt nach, nichts wird geändert):

1. `*:* = deny` (Baseline: alles verboten)
2. `read * = ask` (Lesen fragt nach – in Workspace)
3. `external_directory * = deny` (Extern gesperrt)
4. `edit * = deny`, `write * = deny`, `patch * = deny` (Nichts ändern)
5. `shell * = ask` (Shell fragt nach – inkl. git, ls, cat)
6. `glob * = ask`, `grep * = ask` (Suche fragt nach)
7. `skill * = ask`, `subagent * = ask` (Skill/Subagent fragen nach)
8. `webfetch * = ask`, `websearch * = ask` (Web fragt nach)
9. `question * = ask` (Fragen fragen nach)
10. `read *.env = ask`, `read *.env.* = ask`, `read *.env.example = ask` (Secrets)

### Engine.java: Default-Permissions
- `agentProfile()`: Leere Permissions → `ContextBuilder.leastPrivilegeDefaults()` statt `*:*=allow`
- `ContextBuilder`-Instantiierung: `leastPrivilegeDefaults()` als defaultPermissions übergeben

### Implizite Regeln (dokumentiert)
Bei echtem Least Privilege gibt es **keine** impliziten Allow-Regeln.
Jede Aktion fragt einzeln nach (ask), außerhalb des Workspace wird alles denied.
Die "Implikationen" sind jetzt explizite ask-Regeln, keine auto-allows.

### Plan-Ordner im Workspace-Root (EngineConfig.java)
Der Plan-Ordner wurde von `~/.opencode/plan` nach `<workspace>/.opencode/plan` verschoben:
- Innerhalb des Workspace → keine `external_directory`-Permission nötig
- User-isoliert (jeder User hat eigenen Plan-Ordner)
- `planDirectory()` nutzt jetzt den Workspace-Pfad

### Plan-Ordner: `.opencode/plan/` → `plans/` (Workspace-Root)
Der Plan-Ordner wurde von `.opencode/plan/` nach `plans/` (im Workspace-Root) umbenannt:
- Nicht mehr OpenCode-kompatibel (war `~/.opencode/plan`)
- Innerhalb des Workspace → keine `external_directory`-Permission nötig
- User-isoliert (jeder User hat eigenen Plan-Ordner unter `user-ws/<user>/plans/`)
- `planDirectory()` nutzt jetzt `<workspace>/plans`

### Default Build/Plan Agents (EngineConfig.java)
Die Default-Agents nutzen jetzt `leastPrivilegeDefaults()` statt `*:* = ALLOW`:

**Build-Agent:**
- `*:* = deny` (Baseline aus Defaults)
- `read * = allow`, `edit * = allow`, `write * = allow`, `patch * = allow` (explizit)
- `shell * = ask` (nachfragen)
- `external_directory planDir/* = allow` (Plan-Ordner)

**Plan-Agent:**
- `*:* = deny` (Baseline aus Defaults)
- `edit * = deny` (keine Änderungen)
- `read * = allow` (lesen erlaubt)
- `shell * = ask` (nachfragen)
- `external_directory planDir/* = allow` (nur Plan-Ordner)

Unterschied: Build-Agent darf editieren, Plan-Agent nicht. Beide nutzen Least-Privilege-Defaults.

**Hinweis:** QOC hat keine echten impliziten Regeln – jede Aktion ist unabhängig.
Die Konfiguration macht die Implikationen explizit durch separate Regeln.

## 2. Auth0 OIDC Integration (GCP VM)

### Auth0-Konfiguration
- **Tenant:** `dev-1kxf4iy7txwbmdks.us.auth0.com`
- **Application:** QOC (Regular Web Application)
- **API/Audience:** `qoc-engine`
- **Users:** `admin@qoc.test` / `login` (role: admin), `user@qoc.test` / `login` (role: user)
- **Post-Login Action:** `qoc-role-claim` – setzt Namespaced Claims:
  - `https://qoc.augmentia.de/role` → "admin" oder "user"
  - `https://qoc.augmentia.de/roles` → ["admin"] oder ["user"]
  - `https://qoc.augmentia.de/username` → E-Mail

### OidcPrincipalProducer (Auth0 Claim-Mapping)
- Liest `realm_access.roles` (Keycloak) + namespaced Claims (Auth0)
- Iteriert über alle Claim-Namen, prüft `endsWith("/roles")` und `endsWith("/role")`
- `stripQuotes()` entfernt Anführungszeichen aus Role-Strings
- Mapping: Auth0 "admin" → QOC "admin", Auth0 "user" → QOC "user"

### GCP VM
- **Domain:** test.schippel.info + test.augmentia.de
- **Service:** active (systemd, native binary)
- **Agents:** research-agent, research-orchestrator in `/data/workspace/.opencode/agents/`
- **Nginx:** OIDC-Modus (kein Basic Auth), serviert `/config.js` aus `/etc/qoc/ui-config.js`
- **Login-Button:** Sichtbar auf beiden Domains (statisches index.html via Nginx)

### Verifiziert
- Admin-Token: role=admin, roles=['admin'] → /api/metrics: 200
- User-Token: role=user, roles=['user'] → /api/metrics: 403
- User kann Sessions erstellen und Prompts ausführen
- User kann keine Agents löschen (403)
