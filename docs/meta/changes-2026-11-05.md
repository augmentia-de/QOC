# Changes – 05.11.2026

## 1. Least-Privilege Permission System

### ContextBuilder: defaultPermissions
- **File:** `engine/src/main/java/de/augmentia/oc/engine/runtime/context/ContextBuilder.java`
- New field `defaultPermissions` (List<Rule>)
- New constructor with `List<Rule> defaultPermissions` parameter
- Existing constructors delegate with `List.of()` (no change for existing callers)
- `prepare()` prepends `defaultPermissions` before Agent and Session rules

### Static Factory: leastPrivilegeDefaults()
Static method in `ContextBuilder` returns a preconfigured rule set
(**real least privilege** – deny all, everything asks, nothing is changed):

1. `*:* = deny` (Baseline: everything forbidden)
2. `read * = ask` (Reading asks – in workspace)
3. `external_directory * = deny` (External locked out)
4. `edit * = deny`, `write * = deny`, `patch * = deny` (Nothing changes)
5. `shell * = ask` (Shell asks – incl. git, ls, cat)
6. `glob * = ask`, `grep * = ask` (Search asks)
7. `skill * = ask`, `subagent * = ask` (Skill/Subagent ask)
8. `webfetch * = ask`, `websearch * = ask` (Web asks)
9. `question * = ask` (Questions ask)
10. `read *.env = ask`, `read *.env.* = ask`, `read *.env.example = ask` (Secrets)

### Engine.java: Default-Permissions
- `agentProfile()`: Empty Permissions → `ContextBuilder.leastPrivilegeDefaults()` instead of `*:*=allow`
- `ContextBuilder` instantiation: `leastPrivilegeDefaults()` passed as defaultPermissions

### Implicit rules (documented)
With real least privilege there are **no** implicit allow rules.
Every action asks individually (ask), outside the workspace everything is denied.
The "implications" are now explicit ask rules, not auto-allows.

### Plan folder in workspace root (EngineConfig.java)
The plan folder was moved from `~/.opencode/plan` to `<workspace>/.opencode/plan`:
- Inside the workspace → no `external_directory` permission needed
- User-isolated (each user has their own plan folder)
- `planDirectory()` now uses the workspace path

### Plan folder: `.opencode/plan/` → `plans/` (workspace root)
The plan folder was renamed from `.opencode/plan/` to `plans/` (in the workspace root):
- No longer OpenCode-compatible (was `~/.opencode/plan`)
- Inside the workspace → no `external_directory` permission needed
- User-isolated (each user has their own plan folder under `user-ws/<user>/plans/`)
- `planDirectory()` now uses `<workspace>/plans`

### Default Build/Plan Agents (EngineConfig.java)
The default agents now use `leastPrivilegeDefaults()` instead of `*:* = ALLOW`:

**Build-Agent:**
- `*:* = deny` (Baseline from defaults)
- `read * = allow`, `edit * = allow`, `write * = allow`, `patch * = allow` (explicit)
- `shell * = ask` (ask)
- `external_directory planDir/* = allow` (Plan folder)

**Plan-Agent:**
- `*:* = deny` (Baseline from defaults)
- `edit * = deny` (no changes)
- `read * = allow` (reading allowed)
- `shell * = ask` (ask)
- `external_directory planDir/* = allow` (only plan folder)

Difference: Build agent may edit, plan agent may not. Both use least-privilege defaults.

**Note:** QOC has no real implicit rules – every action is independent.
The configuration makes the implications explicit through separate rules.

- Reads `realm_access.roles` (Keycloak) + namespaced claims (Auth0)

- `stripQuotes()` removes quotation marks from role strings
- Mapping: Auth0 "admin" → QOC "admin", Auth0 "user" → QOC "user"
