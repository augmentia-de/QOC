# Changes since 2026-11-05 (snapshot 2026-11-22)

This file summarizes the work merged after `changes-2026-11-05.md`. The history is
dominated by the workflow stack, RBAC/security, structured outputs, the ACP adapter,
tool configuration and the saga/undo MVP. Individual commits are referenced where useful.

## 1. Architecture & modules

- Repository split into `engine`, `quarkus`, `workflow-runner`, `cli`; the React frontend
  lives in `reactflow/`, the terminal UI in `tui/`, deployment assets in `deploy/`.
- `workflow-runner` is a **library** (no Temporal dependency): store, compiler, executor,
  sub-workflows, node contracts, context assembly, generation and main runner.
  Temporal and `temporal-ui` were removed.
- `quarkus` remains the outer skin: HTTP/SSE, OIDC/Keycloak, MCP/A2A resources, ACP,
  RBAC guards, workflow wiring and the static UI.

## 2. Workflow engine (`workflow-runner`)

- `GraphCompiler`, `WorkflowExecutor`, `DefaultNodeDispatcher`, `TopologicalSort`,
  `ConditionEvaluator`, `SubWorkflowExpander`, `TemplateResolver`, `ContextAssembler`,
  `ContextBudgetGate`, `WorkflowRunJournal`, `WorkflowRunnerMain`.
- Stores: `InMemoryWorkflowStore`, `SqliteWorkflowStore`, `PostgresWorkflowStore`;
  `AgentStore` equivalents (`InMemory`, `Sqlite`, `Postgres`).
- Node contracts: `NodeContractValidator`, `WorkflowContractValidator`,
  `ContractViolationException`, LLM-based semantic review (`validateWithLlm`),
  `verifyOnStop` integration.
- Structured outputs: `StructuredOutputConverter`, `JavaSourceToJsonSchema`,
  `YamlToJsonSchema`, `OpenApiToJsonSchema`, `SchemaSource`, `strict` flag,
  automatic `contextRefs`, configurable output limit.
- Context agents: `compactAfterRun`, compact nodes, default user task
  `engine.context.default-task` (default `start`); no `title`/`mcpArgs` misuse.
- Workflow safety: explicit workflow loop (no implicit LLM fallback), configurable
  `ENGINE_WORKFLOW_MAX_STEPS`, `maxTurns=0` (unlimited) for build/plan agents.
- `WorkflowGenerator`, `GenerateConfig`, `TypeSafeDecisionClient` (env config, validation,
  retries, logging, input truncation).

## 3. Workflow UI (`reactflow/`, served under `/workflow/`)

- Pages: Workflows, Runs, Agents, Dashboard, Generate, HITL, LLM trace, MCP servers,
  Observe, Settings, Testbench, Files, A2A.
- ReactFlow editor: node property panel, data-contract section, edge conditions,
  multi-select tools, data-piping hints, ELK layout, explicit “Apply JSON”, drag fixes,
  node/edge persistence.
- i18n (DE/EN), mobile optimizations, agent edit overlay, agent grouping/sorting,
  Agent Store CRUD, SSOT reload after save.
- Chat UI (`/`): workspace switcher, files/settings pages, file tree/viewer, LLM trace
  panel, mobile Send/Cancel fix (`uid()` works in insecure contexts).

## 4. Security & RBAC

- Principal propagation through `ToolContext` and `QocEngine`; `ToolAuthorizer` audit
  metadata.
- HMAC `ToolTokenService` / `HmacToolTokenService`; `SecureRestTool`; MCP tool token
  forwarding with config allow-list; A2A OIDC token forwarding; protected admin ping.
- RBAC foundation: `Principal.system()`, system-token auth, `ownerId`/`rolesAllowed` on
  workflow/agent definitions, journal `ownerId`, owner filtering, agent-store guards,
  `ExecutionGuards`, `SessionAccessGuard`, ownership integration tests.
- Local Keycloak deployment (`deploy/keycloak`, `deploy/docker-oidc-native`) and OIDC
  token usage; Auth0 remains spec-only.
- Workflow-OIDC plan (RBAC, system user, OIDC) and `docs/engineering/Workflow-OIDC.md`.
  Core RBAC/system-token/ownerId is implemented; Auth0 mapping and the full OIDC phase
  set remain spec-only.

## 5. MCP server persistence

- V12 migration (`V12__mcp_server.sql`) and `SqlMcpServerStore` /
  `McpServerPersistence`; `McpServerResource` CRUD + reload; UI page `McpServers`.

## 6. ACP adapter

- `docs/plans/acp-adapter.md` (bidirectional JSON-RPC over stdio).
- `AcpConfig`, `AcpTransport`, `AcpServer`, `AcpSessionManager`, `AcpHandler`,
  `AcpStartup`: `session/new`, `prompt`, `cancel`, `load`, `list`, `delete`, `close`,
  `config`, `mode`, `auth` (Phase 2–5; Phase 6 tests outstanding).

## 7. Tool configuration & permissions

- Dynamic tool list with search, drag-drop, namespaces and stale handling
  (`AgentConfigOverlay`).
- Presets (`readonly`, `retrieval`, `editor`, `full`, `context-agent`) materialize into
  concrete `tools` + `permissions` JSON (`agentPresets.ts`).
- Permission-check endpoint (`AgentStoreResource`), `rolesAllowed` vs `permissions`
  semantics clarified; least-privilege default; empty tool list = none, `*` = all.
- Tool-permission action alignment: `write`/`edit`/`patch`/`delete` = `edit`;
  skill tools = `skill_load`/`skill_list`.
- Agent editor: no model persistence; default system prompt when empty; `active` flag
  persisted; agents sorted by group/name; Engine Agents page removed.
- Saga/undo: `UndoSpec`, `UndoRegistry`, `UndoToolFactory`, `UndoRuntime`, generated
  `undo_<tool>`, `write → delete` (creations only), `worktree_create → worktree_remove`;
  complete saga plan `saga-orchestration.md` (M5–M10, opt-in `SagaPolicy`).

## 8. Deployment

- `deploy/docker-dev` (JVM dev, 8070), `deploy/docker-dev-native` (native, 8082),
  `deploy/docker-oidc-native` (Keycloak), `deploy/gcp-native-memory` (no DB),
  `deploy/aws-ecs-minimal`, `deploy/gcp-vm`, `deploy/keycloak`.
- Workspace points at the `qoc` folder on host and docker-dev; relative paths;
  `ENGINE_PERMISSION_DEFAULT=allow-all`, `ASK_MODE=interactive` on host, `allow` in
  docker-dev (no prompts in dev).
- Native memory mode, GCP native, ECS/Fargate; remote debug (JDWP 5005) and file logging
  (2 MiB × 10) in start scripts.
- Sandbox fallback: `SandboxedProcessRunner` probes `bwrap -- true`; falls back to direct
  execution (`ENGINE_SHELL_SANDBOX_ENABLED=false` on hosts without user namespaces).
